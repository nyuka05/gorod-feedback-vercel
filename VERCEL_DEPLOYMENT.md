# Очень подробная инструкция по публикации проекта на Vercel

## 1. Что уже подготовлено

Эта ветка проекта адаптирована для Vercel:

- сборка выполняется стандартным Next.js, без Vinext и Cloudflare Worker;
- Cloudflare D1 заменён на удалённую SQLite-совместимую базу Turso;
- пароль администратора и секрет сессии читаются из переменных окружения Vercel;
- карточки участников показывают только ФИ и название проекта, без фотографий;
- добавлен повторно запускаемый сценарий миграции базы `pnpm db:migrate`;
- текущая версия для Cloudflare сохранена в ветке `main`, а Vercel-версия находится в ветке `codex/vercel-deployment`.

Vercel — облачный хостинг. После публикации компьютер можно выключить: сайт и база продолжат работать.

## 2. Что понадобится

Перед началом подготовьте:

1. аккаунт GitHub: <https://github.com/>;
2. аккаунт Vercel: <https://vercel.com/> — удобнее зарегистрироваться через GitHub;
3. Node.js 22.13 или новее: <https://nodejs.org/>;
4. Git for Windows: <https://git-scm.com/download/win>;
5. доступ к папке этого проекта;
6. отдельный надёжный пароль для страницы `/admin`.

Turso будет подключён из кабинета Vercel. Отдельно устанавливать сервер базы данных не нужно.

## 3. Перед публикацией

### 3.1. Проверьте ветку

Откройте PowerShell в папке проекта и выполните:

```powershell
git branch --show-current
```

Ожидаемый ответ:

```text
codex/vercel-deployment
```

Не переключайте эту папку на `main`, если хотите сохранить именно Vercel-версию.

### 3.2. Не публикуйте секреты

Файлы `.env`, `.env.local` и другие `.env*` уже исключены из Git. Никогда не добавляйте их принудительно и не отправляйте содержимое этих файлов в чат или почту.

Проверить состояние можно так:

```powershell
git status --short
```

В списке не должно быть `.env.local`.

## 4. Создание репозитория GitHub

### 4.1. Создайте пустой репозиторий

1. Откройте <https://github.com/new>.
2. В поле **Repository name** укажите, например, `gorod-feedback-vercel`.
3. Выберите **Private**, пока выполняется настройка. Позже репозиторий можно оставить закрытым — публичности сайта это не мешает.
4. Не включайте пункты **Add a README**, **Add .gitignore** и **Choose a license**, потому что эти файлы уже есть в проекте.
5. Нажмите **Create repository**.

### 4.2. Отправьте Vercel-ветку как `main`

На странице нового репозитория скопируйте HTTPS-адрес. Он выглядит так:

```text
https://github.com/ВАШЕ_ИМЯ/gorod-feedback-vercel.git
```

В PowerShell выполните, заменив адрес на свой:

```powershell
git remote add github-vercel https://github.com/ВАШЕ_ИМЯ/gorod-feedback-vercel.git
git push -u github-vercel codex/vercel-deployment:main
```

Если GitHub попросит войти, завершите вход в открывшемся окне браузера.

Проверьте репозиторий на GitHub: в нём должны появиться `app`, `components`, `db`, `drizzle`, `public`, `scripts`, `package.json` и `VERCEL_DEPLOYMENT.md`.

Если команда сообщает, что имя `github-vercel` уже существует, сначала проверьте его:

```powershell
git remote -v
```

Не удаляйте и не заменяйте неизвестный адрес. Можно использовать другое имя, например `vercel-repo`.

## 5. Создание проекта Vercel

1. Войдите на <https://vercel.com/> через GitHub.
2. Нажмите **Add New → Project**.
3. Если Vercel просит разрешение GitHub, предоставьте доступ только к репозиторию `gorod-feedback-vercel`.
4. Найдите созданный репозиторий и нажмите **Import**.
5. Укажите имя проекта, например `gorod-feedback`.
6. В поле **Framework Preset** должно автоматически определиться **Next.js**.
7. **Root Directory** оставьте `./`.
8. Команду сборки оставьте стандартной `pnpm build` или пустой — Vercel возьмёт её из `package.json`.
9. **Output Directory** не задавайте. Для Next.js она определяется автоматически.
10. Нажмите **Deploy**.

Первая сборка должна завершиться успешно, но данные ещё не заработают: сначала нужно подключить Turso и секреты. Это нормально.

## 6. Подключение базы Turso

### 6.1. Создайте базу

1. Откройте созданный проект в Vercel.
2. Перейдите в раздел **Storage**.
3. Нажмите **Create Database** или **Browse Storage**.
4. Выберите **Turso Cloud** в Marketplace.
5. Нажмите **Install** или **Add Integration**.
6. Разрешите интеграции доступ к текущему проекту.
7. Создайте новую базу, например `gorod-feedback-db`.
8. Если предлагается выбор региона, выберите ближайший доступный к аудитории сайта. Функции Vercel и база желательно должны находиться географически близко.
9. Подключите базу минимум к окружениям **Production** и **Preview**. Для локальной разработки также включите **Development**.

После подключения Vercel должен автоматически создать две переменные:

```text
TURSO_DATABASE_URL
TURSO_AUTH_TOKEN
```

Проверьте их наличие в **Project → Settings → Environment Variables**. Значения копировать в исходный код не нужно.

### 6.2. Если Turso подключается без Marketplace

Если интеграция недоступна, создайте базу в <https://turso.tech/> и вручную добавьте в Vercel:

- `TURSO_DATABASE_URL` — адрес вида `libsql://имя-базы-аккаунт.turso.io`;
- `TURSO_AUTH_TOKEN` — токен с правом записи.

Добавьте обе переменные для Production, Preview и Development.

## 7. Пароль администратора и секрет сессии

Откройте **Project → Settings → Environment Variables** и добавьте:

```text
ADMIN_PASSWORD
ADMIN_SESSION_SECRET
```

### 7.1. ADMIN_PASSWORD

Укажите отдельный сложный пароль длиной не менее 12–16 символов. Не используйте пароль от Vercel, GitHub или рабочей почты.

### 7.2. ADMIN_SESSION_SECRET

Создайте случайную строку. В PowerShell можно выполнить:

```powershell
$secretBytes = New-Object byte[] 48
[Security.Cryptography.RandomNumberGenerator]::Fill($secretBytes)
[Convert]::ToBase64String($secretBytes)
```

Скопируйте выведенное значение в `ADMIN_SESSION_SECRET`. Саму команду сохранять не нужно.

Для каждой переменной отметьте **Production**. Если будете проверять Preview-развёртывания, отметьте также **Preview** и **Development**.

После добавления или изменения переменных всегда требуется новое развёртывание: старое развёртывание не получит новые значения автоматически.

## 8. Подготовка базы данных

Миграцию удобно запустить с вашего компьютера один раз.

### 8.1. Вход и привязка Vercel CLI

В PowerShell в папке проекта выполните:

```powershell
pnpm dlx vercel login
pnpm dlx vercel link
```

При `vercel link`:

1. подтвердите текущую папку;
2. выберите свою команду или личный аккаунт Vercel;
3. выберите существующий проект `gorod-feedback`;
4. не создавайте второй проект с похожим названием.

### 8.2. Загрузите переменные Development

```powershell
pnpm dlx vercel env pull .env.local
```

Команда создаст локальный `.env.local`. Проверьте только имена переменных, не показывая значения:

```powershell
Select-String -Path .env.local -Pattern "^(TURSO_DATABASE_URL|TURSO_AUTH_TOKEN|ADMIN_PASSWORD|ADMIN_SESSION_SECRET)="
```

Должно быть найдено четыре строки. Если каких-то строк нет, вернитесь в настройки Vercel и подключите переменные к окружению Development, затем повторите `vercel env pull`.

### 8.3. Примените миграции

```powershell
pnpm install --frozen-lockfile
pnpm db:migrate
```

Ожидаемый результат при первом запуске:

```text
applied 0000_daffy_bucky.sql
applied 0001_funny_lucky_pierre.sql
```

Повторный запуск безопасен и должен показать `skip` для уже применённых файлов.

Никогда не редактируйте применённый SQL-файл миграции. Для будущего изменения схемы создавайте новый файл через `pnpm db:generate`.

## 9. Локальная проверка

Запустите:

```powershell
pnpm dev
```

Откройте:

- площадка: <http://localhost:3000>;
- административная часть: <http://localhost:3000/admin>.

Войдите с `ADMIN_PASSWORD`. При первом обращении приложение создаст недостающие служебные объекты и, если таблица участников пустая, добавит демонстрационный список.

Проверьте:

1. открывается стартовая страница;
2. отображаются участники;
3. в `/admin` работает пароль;
4. добавляется тестовый участник;
5. отправляется оценка от участника;
6. повторная отправка от того же имени обновляет существующую оценку;
7. трекер, организатор и методист создают независимые отзывы;
8. видны текущие суммы лайков;
9. стена сообщений открывается;
10. закрытие приёма блокирует новые оценки;
11. Excel-экспорт скачивается.

Для остановки локального сервера нажмите `Ctrl+C`.

## 10. Повторное развёртывание после настройки

Переменные окружения применяются только к новому развёртыванию.

В кабинете Vercel:

1. откройте **Deployments**;
2. найдите последнее развёртывание;
3. откройте меню с тремя точками;
4. нажмите **Redeploy**;
5. не выбирайте старый кэш, если интерфейс предлагает пересобрать без него;
6. дождитесь статуса **Ready**.

Либо выполните из папки проекта:

```powershell
pnpm dlx vercel --prod
```

После публикации Vercel покажет адрес вида:

```text
https://gorod-feedback.vercel.app
```

## 11. Финальная проверка опубликованного сайта

Проверяйте именно Production-адрес в режиме инкогнито или с телефона через мобильный интернет:

1. главная страница загружается без входа в Vercel;
2. логотип и компактные карточки без фотографий видны;
3. `/api/bootstrap` возвращает JSON, а не ошибку 500;
4. отправленный голос появляется в сумме;
5. сообщение появляется на стене;
6. `/admin` не открывает данные без пароля;
7. правильный пароль открывает панель;
8. закрытие и повторное открытие приёма работают;
9. экспорт итогов скачивается.

После проверки удалите тестовые отзывы через **Админка → Настройки → Удалить отзывы**.

## 12. Импорт настоящих участников

В `/admin` можно загрузить XLSX, XLS или CSV.

Для участников используйте колонки:

```text
id, fullName, project, sortOrder
```

Также поддерживаются русские заголовки `ID`, `ФИ`, `Проект`, `Название проекта`, `Порядок`.

Для организаторов достаточно:

```text
id, fullName
```

Каждому человеку нужен постоянный уникальный `id`. Не меняйте `id` после начала голосования: он связывает человека с оценками и стеной сообщений.

Данные из прежней Cloudflare-базы автоматически в Turso не переносятся. Если в действующей версии уже есть важные результаты, сначала скачайте Excel в старой административной панели и не удаляйте старую площадку. Для полного переноса голосов потребуется отдельная миграция данных.

## 13. Подключение собственного домена

1. В Vercel откройте **Project → Settings → Domains**.
2. Добавьте домен или поддомен, например `feedback.example.ru`.
3. Vercel покажет DNS-запись, которую нужно добавить у регистратора домена.
4. Дождитесь статуса **Valid Configuration**.
5. HTTPS-сертификат Vercel выпустит автоматически.

До завершения настройки домена адрес `*.vercel.app` продолжит работать.

## 14. Как публиковать дальнейшие изменения

Работайте в локальной ветке `codex/vercel-deployment`, затем выполняйте:

```powershell
git add app components db lib public scripts package.json pnpm-lock.yaml
git commit -m "Описание изменения"
git push github-vercel codex/vercel-deployment:main
```

Vercel автоматически создаст новое Production-развёртывание после обновления GitHub-ветки `main`.

Перед отправкой изменений рекомендуется выполнить:

```powershell
pnpm test
pnpm lint
pnpm build
```

Если менялась схема `db/schema.ts`:

```powershell
pnpm db:generate
pnpm db:migrate
```

Проверьте созданный SQL-файл до публикации.

## 15. Откат версии

Если новое изменение сломало сайт:

1. откройте **Vercel → Deployments**;
2. найдите предыдущую рабочую версию;
3. откройте её меню;
4. выберите **Promote to Production** или **Rollback**, в зависимости от интерфейса;
5. проверьте сайт после переключения.

Откат кода не откатывает базу Turso. Поэтому опасные изменения структуры базы должны выполняться отдельными миграциями с резервной копией.

## 16. Типичные ошибки

### На странице нет участников, `/api/bootstrap` возвращает 500

Проверьте наличие `TURSO_DATABASE_URL` и `TURSO_AUTH_TOKEN` в Production. После исправления выполните Redeploy.

### `TURSO_DATABASE_URL is required`

База не подключена к нужному окружению. В Storage откройте Turso и добавьте текущий проект/окружение.

### `401`, `unauthorized` или ошибка токена Turso

Токен базы отсутствует, истёк либо создан без права записи. Переподключите интеграцию или создайте новый токен, обновите переменную и выполните Redeploy.

### Пароль администратора всегда неверный

Проверьте `ADMIN_PASSWORD` и `ADMIN_SESSION_SECRET` в Production. После их изменения обязательно выполните Redeploy. Не добавляйте кавычки вокруг значения в интерфейсе Vercel.

### Сайт доступен только после входа в Vercel

Откройте **Project Settings → Deployment Protection** и убедитесь, что Production-развёртывание не закрыто защитой Vercel Authentication. Административная страница уже защищена собственным паролем.

### Миграция сообщает, что применённый файл изменён

Верните старому SQL-файлу первоначальное содержимое. Новое изменение оформите отдельной миграцией. Не удаляйте запись из `app_migrations` вручную.

### GitHub не запускает новое развёртывание

Проверьте:

1. что изменения появились в GitHub;
2. что Production Branch в Vercel — `main`;
3. что интеграция Vercel имеет доступ к репозиторию;
4. что в Deployments нет ожидающего подтверждения или ошибки сборки.

## 17. Безопасность и эксплуатация

- Не публикуйте `.env.local` и токены.
- Не используйте `NEXT_PUBLIC_` для секретов.
- Перед мероприятием смените демонстрационный пароль.
- Дайте доступ к Vercel, GitHub и Turso только организаторам.
- Перед сбросом отзывов скачивайте Excel-экспорт.
- Не меняйте идентификаторы участников после начала голосования.
- Проведите репетицию с несколькими телефонами и одновременными голосами.
- Проверяйте лимиты бесплатных тарифов Vercel и Turso перед массовым мероприятием.
- Текущая модель идентификации остаётся организационной: любой человек со ссылкой может выбрать имя из списка и изменить голос этого отправителя.
